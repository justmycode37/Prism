Proposed design · SOLUSDT

The trading loop — repeats when new information arrives

1. Watch

Prism receives new market and account data.

→
2. Decide

Sol reads saved memory and Luna advice. Trade or wait?

→
3. Act

Prism checks risk limits and handles orders.

→
4. Remember

Save decisions, fills and results. Refresh the notes.

↶ The next Sol call reads this saved memory. The loop repeats.

Protection runs independently

Position monitoring and protective order handling continue while Sol is thinking.

The learning loop — runs after outcomes are known

Review trades

What happened? Was there a repeatable problem?

→
Suggest a change

Write a possible lesson, linked to the evidence.

→
Paper-test it

Compare the change with the current playbook.

Pass →Adopt under the approved rules; future Sol calls read the updated playbook.

Fail →Keep the current playbook and record what failed.

Database = factual history. Markdown = readable notes. A proposed lesson needs evidence before it changes trading.
